# Anime Frame Quiz — لعبة تخمين فريمات الأنمي (Multiplayer حقيقي)

**التقنية:** React + Vite (واجهة) · Node + Express + Socket.IO (خادم، مصدر الحقيقة) · SQLite عبر `node:sqlite` (بدون حزم native).

## التشغيل محليًا
```bash
npm install
npm run build
ADMIN_KEY=سر-قوي npm start        # http://localhost:3000
# للتطوير: npm run dev:server  ثم في طرفية أخرى  npm run dev:client
npm test                           # اختبار تكاملي للـ Buzzer والإجابات والمؤقتات
```
يتطلب Node 22.13 أو أحدث. للعب من أجهزة أخرى على نفس الشبكة افتح `http://IP-جهازك:3000`.

## ⚠️ الصور (مهم)
قاعدة البيانات تحتوي **66 شخصية** (Naruto, Dragon Ball, One Piece, Bleach) بأسمائها العربية والإنجليزية والإجابات البديلة والصعوبة، لكن **بدون أي صور**.
الفريمات محمية بحقوق النشر ولم أستطع جلبها، ولن أضع صورًا لا علاقة لها. أضف روابط الصور من «إدارة الشخصيات والصور» في الصفحة الرئيسية (تحتاج `ADMIN_KEY`).
- الشخصية بلا صور لا تظهر في اللعب؛ وإن كانت الصور أقل من عدد الجولات تُقلَّص الجولات تلقائيًا (لا تكرار للفريمات في المباراة).
- لتنويع اللقطات أضف عدة صور لكل شخصية (لقطات من حلقات مختلفة، لا الصورة الرسمية فقط).
- استخدم روابط مباشرة (https) لصور تملك حق استخدامها.

## النشر على Render
1. ارفع المشروع إلى GitHub.
2. Render ← New ← **Blueprint** واختر المستودع (يقرأ `render.yaml`) أو New Web Service يدويًا: Build `npm install --include=dev && npm run build` · Start `npm start` · متغير `NODE_VERSION=22`.
3. اضبط `ADMIN_KEY` (يولّده Blueprint تلقائيًا؛ اطّلع عليه من Environment).
4. **قاعدة البيانات:** المشروع **لا يعتمد على قرص دائم**. يُحفظ SQLite افتراضيًا في `./data/game.db` (قرص مؤقت يعمل على الخطة المجانية)، وإن لم يكن المسار قابلًا للكتابة يتراجع إلى مجلد temp مع تحذير في السجل. **على القرص المؤقت تُمسح الصور المضافة والإحصائيات عند كل إعادة نشر/تشغيل.** للحفظ الدائم أنشئ Persistent Disk (خطة مدفوعة) على `/var/data` وأضف `DB_PATH=/var/data/game.db` (الأسطر جاهزة كتعليق في `render.yaml`).
5. الخطة المجانية تنام بعد 15 دقيقة خمول (أول فتح يتأخر ~50 ث). يعمل WebSocket بدون إعداد إضافي. حالة الغرف في الذاكرة، فاستخدم نسخة واحدة (Instance واحد).

## كيف يعمل الـ Buzzer
الخادم Node أحادي الخيط: أول حدث `buzz` يصل ويُعالَج يحجز الفرصة (`buzzer = id`) ويُرفض ما بعده؛ لا يُستخدم توقيت أي جهاز. عند الخطأ أو انتهاء وقت التخمين يُفتح الزر لبقية اللاعبين (اللاعب المخطئ ممنوع في نفس السؤال). الإجابة الصحيحة 100 نقطة (+ حتى 50 مكافأة سرعة اختيارية).

## الاتصال والانقطاع
- يظهر شريط تنبيه عند فشل الاتصال بالخادم أو انقطاعه مع إعادة محاولة تلقائية، وتُعطَّل الواجهة حتى يعود الاتصال.
- عند انقطاع لاعب يُزال من الغرفة ويُبلَّغ الجميع (وتُحسم محاولة الإجابة إن كان صاحبها). **لا توجد إعادة انضمام تلقائية**: بعد عودة اتصاله يرجع للرئيسية ويدخل بالكود من جديد. المضيف ينتقل تلقائيًا لأقدم لاعب. إن بقي لاعب واحد أثناء المباراة تنتهي تلقائيًا.

## الإدارة
`POST /api/images` يتطلب الترويسة `x-admin-key` المطابقة لـ `ADMIN_KEY` (مقارنة ثابتة الزمن، وحد 10 محاولات فاشلة/10 دقائق لكل IP). إن لم يُضبط `ADMIN_KEY` تُرفض كل الطلبات.
